# ระบบสแกน QR สั่งอาหารที่โต๊ะและสั่งรับเอง (ร้านเดียว)

ลูกค้าสแกน QR ที่โต๊ะ → เลือกเมนู → กดสั่ง → ระบบแสดงยอดที่ต้องชำระ
หรือลูกค้าสแกน QR ที่เคาน์เตอร์ → กรอกชื่อ → ระบบออกเลขคิว → รับสินค้าที่เคาน์เตอร์
พนักงานแจ้งยอดและให้ลูกค้าสแกน QR บัญชีร้าน ลูกค้าพิมพ์ยอดเอง และพนักงานกด "รับเงินแล้ว" เมื่อตรวจพบเงินเข้าบัญชีจริง

## หน้าจอทั้งหมด
| ที่อยู่ | ใครใช้ | ทำอะไร |
|---|---|---|
| `/t/5` | ลูกค้า (โต๊ะ 5) | ดูเมนู สั่ง จ่ายเงิน ดูสถานะ |
| `/pickup` | ลูกค้ารับเอง | ดูเมนู กรอกชื่อ รับเลขคิว และดูสถานะ |
| `/pos` | พนักงานหน้าเคาน์เตอร์ | เลือกสินค้า รับเงิน ออกเลขคิว หรือส่งรายการไปจอรับออเดอร์ |
| `/kitchen` | พนักงาน/แคชเชียร์ (แท็บเล็ต) | รับออเดอร์ แจ้งพร้อมรับ ยืนยันรับเงิน ยกเลิก |
| `/admin` | เจ้าของร้าน | แก้เมนู/ราคา เปิด–ปิดรับเอง พิมพ์ QR ดูสรุปยอด |

`/pos` และ `/kitchen` ใช้ PIN พนักงาน ส่วน `/admin` ใช้ PIN แอดมินแยกต่างหาก

## รันบนเครื่องตัวเอง (ทดลอง)
ต้องมี Node.js 18 ขึ้นไป
```
npm install
STAFF_PIN=รหัสพนักงาน ADMIN_PIN=รหัสเจ้าของร้าน npm start
```
เปิด http://localhost:3000/kitchen (ล็อกอินด้วย PIN) แล้วลองสั่งที่ http://localhost:3000/t/1 หรือ http://localhost:3000/pickup

## เช็กลิสต์ก่อนเปิดใช้จริง (สำคัญ)
1. **ตั้ง `STAFF_PIN` และ `ADMIN_PIN` ใหม่** — ค่าเริ่มต้นคือ `1234` สำหรับพนักงานและ `5678` สำหรับแอดมิน ต้องตั้งเป็นคนละรหัสก่อนใช้งานจริง
2. **เตรียม QR บัญชีร้านให้พนักงานแต่ละคนถือไว้** — ลูกค้าจะสแกนและพิมพ์ยอดเอง ให้ใช้บัญชีของร้าน พิมพ์ชื่อร้านใต้ QR และลองสแกนเพื่อตรวจชื่อบัญชีก่อนเปิดใช้งาน
3. **เปิดแจ้งเตือนเงินเข้าของแอปธนาคารร้านไว้** และให้กด "รับเงินแล้ว" ต่อเมื่อเห็นเงินเข้าจริง ไม่ดูแค่สลิปที่ลูกค้าโชว์
   (ระบบนี้ไม่รู้เองว่าลูกค้าจ่ายแล้วหรือยัง)
4. **แก้เมนูตัวอย่างเป็นเมนูจริง** ในหน้า `/admin` → เมนู
5. **ตั้งจำนวนโต๊ะ** แล้วพิมพ์ QR จาก `/admin` → QR สั่งซื้อ ซึ่งมีทั้ง QR รับเองที่เคาน์เตอร์และ QR โต๊ะ
6. **บนแท็บเล็ตครัว:** เปิด `/kitchen` แล้วแตะ "เริ่มรับออเดอร์" หนึ่งครั้ง (เบราว์เซอร์ต้องให้แตะก่อนเสียงเตือนจึงจะดัง)
   ระบบจะเตือนซ้ำทุก 20 วินาทีถ้ายังมีออเดอร์ใหม่ที่ไม่มีใครกดรับ ตั้งเสียงแท็บเล็ตให้ดัง และชาร์จไฟไว้
7. **ทดลองกับ 2-3 โต๊ะก่อน** แล้วค่อยขยายทั้งร้าน

## ต้องมี "ที่อยู่จริง" ให้ลูกค้าเข้าถึงได้
QR ที่โต๊ะต้องชี้ไปที่ที่อยู่ที่มือถือลูกค้าเปิดได้ (ไม่ใช่ `localhost`) มี 2 ทางหลัก
- **เช่าเซิร์ฟเวอร์/โฮสต์ออนไลน์** (Render, Railway, Fly.io, VPS ฯลฯ) แล้วตั้งค่า `BASE_URL=https://ชื่อเว็บของคุณ`
  ⚠️ ระบบเก็บข้อมูลเป็นไฟล์ `data/data.json` ต้องเลือกโฮสต์ที่มี **ดิสก์ถาวร (persistent disk)** หรือชี้ `DATA_FILE` ไปที่ดิสก์นั้น
  ไม่งั้นรีสตาร์ทแล้วข้อมูลหาย
- **รันบนคอมในร้าน แล้วเปิดสู่อินเทอร์เน็ตด้วย Cloudflare Tunnel** (ฟรี) — ได้ที่อยู่ https โดยไม่ต้องตั้งค่าเราเตอร์
  ข้อเสีย: คอมต้องเปิดตลอดเวลาที่ร้านเปิด

ใช้ https เสมอเมื่อเปิดใช้จริง (PIN พนักงานส่งผ่านเครือข่าย)

## Deploy ด้วย Render

โปรเจกต์มี `render.yaml` สำหรับสร้าง Node.js Web Service แบบ Free และใช้ Supabase เป็นที่เก็บข้อมูลถาวร

1. ใน Render เลือก **New Blueprint Instance** และเชื่อม repository นี้
2. ใส่ `STAFF_PIN` และ `ADMIN_PIN` ให้เป็นคนละรหัส ห้ามใช้ค่าเริ่มต้น
3. ใส่ `SUPABASE_URL` และ `SUPABASE_SERVICE_ROLE_KEY` จาก Supabase Project Settings → API Keys
4. ตรวจว่าแผนเป็น Free ก่อนกด Apply
5. เมื่อ deploy สำเร็จ เปิด `/admin` และตั้งชื่อร้าน จำนวนโต๊ะ และเมนูก่อนพิมพ์ QR

ก่อนเชื่อมครั้งแรก ให้รันไฟล์ `supabase/schema.sql` ใน Supabase SQL Editor เพื่อสร้างตาราง `app_state` และ bucket `menu-images` ระบบใช้ Secret API Key เฉพาะฝั่งเซิร์ฟเวอร์และไม่ส่งไปยังเบราว์เซอร์ หากไม่ได้ตั้งค่า Supabase ระบบจะย้อนกลับไปใช้ `DATA_FILE` และ `IMG_DIR` ซึ่งบน Render Free เป็นพื้นที่ชั่วคราว

## ตัวแปรที่ตั้งได้ (environment variables)
| ชื่อ | ค่าเริ่มต้น | ความหมาย |
|---|---|---|
| `PORT` | 3000 | พอร์ตเซิร์ฟเวอร์ |
| `STAFF_PIN` | 1234 | PIN เข้าหน้ารับออเดอร์ |
| `ADMIN_PIN` | 5678 | PIN เจ้าของร้านสำหรับหน้าแอดมิน |
| `BASE_URL` | ใช้จากที่อยู่ที่เปิด | ที่อยู่ที่ใช้ทำ QR โต๊ะ |
| `DATA_FILE` | `data/data.json` | ที่เก็บข้อมูลทั้งหมด (สำรองไฟล์นี้ไว้เสมอ) |
| `IMG_DIR` | โฟลเดอร์ `images` ข้างไฟล์ข้อมูล | ที่เก็บรูปเมนู ต้องอยู่บนดิสก์ถาวรและสำรองคู่กับไฟล์ข้อมูล |
| `SUPABASE_URL` | ว่าง | URL ของโปรเจกต์ Supabase; เมื่อตั้งคู่กับ Secret Key จะใช้ Supabase แทนไฟล์ |
| `SUPABASE_SERVICE_ROLE_KEY` | ว่าง | Secret API Key ฝั่งเซิร์ฟเวอร์ ห้ามใส่ในโค้ดหรือส่งให้เบราว์เซอร์ |
| `SUPABASE_BUCKET` | `menu-images` | bucket ส่วนตัวสำหรับรูปเมนู |

## สิ่งที่ระบบทำให้แล้ว
- เซิร์ฟเวอร์คำนวณยอดเองจากราคาในเมนู ไม่เชื่อราคาที่ส่งมาจากมือถือลูกค้า
- โต๊ะที่มีรอบค้างจ่ายครบ 3 รอบ สั่งเพิ่มไม่ได้ (กันคนนอกสแกนสั่งป่วน) และการสั่งแบบรับเองหรือที่โต๊ะที่กดซ้ำเร็วเกินไปจะถูกหน่วง
- ออเดอร์รับเองมีเลขคิวรายวัน `A001`, `A002`, ... พนักงานกด รับออเดอร์ → พร้อมรับที่เคาน์เตอร์ → ลูกค้ารับสินค้าแล้ว
- หน้า POS บันทึกการขายพร้อมวิธีชำระในครั้งเดียว เลือกได้ว่าจะส่งมอบทันทีหรือส่งไปจอรับออเดอร์เพื่อจัดเตรียม และใช้เลขคิวชุดเดียวกับออเดอร์รับเอง
- หน้า POS ปรับตามขนาดจอ: โทรศัพท์เรียงเมนูกับตะกร้าแนวตั้ง ส่วนแท็บเล็ตแสดงเมนูและตะกร้าสองคอลัมน์
- ลูกค้าไม่มีสิทธิ์ยืนยันว่า "จ่ายแล้ว" มีแต่พนักงานเท่านั้น
- ตั้งให้เริ่มทำอาหารได้เฉพาะออเดอร์ที่รับเงินแล้วได้ (หน้าแอดมิน → ตั้งค่า) ข้อดีคือกันไม่จ่าย ข้อเสียคือต้องรอพนักงานกดรับเงินทุกออเดอร์
- เมนูที่ติ๊ก "ไม่มีของ" จะสั่งไม่ได้ทันที
- หมวดเมนูซ่อนจากลูกค้าได้โดยไม่ลบข้อมูล และเปิดกลับได้จากหน้าแอดมิน → เมนู
- ใส่ PIN ผิดครบ 5 ครั้ง ล็อกการลอง 10 นาที
- สรุปยอดรายวัน เทียบกับเงินเข้าบัญชีตอนปิดร้านได้

## บัญชีและรายงาน (หน้า `/admin` → บัญชี)
- **วิธีจ่าย:** ตอนพนักงานกด "ตรวจเงินเข้าแล้ว" บนหน้ารับออเดอร์ มีปุ่ม PromptPay, เงินสด และอื่น ๆ ระบบเก็บวิธีจ่ายและเวลารับเงินไว้
- **คืนเงิน:** ปุ่ม "คืนเงิน" บนการ์ดออเดอร์ที่จ่ายแล้ว ต้องกรอกยอดและเหตุผล เก็บเป็นรายการแยก (ระบบ **ไม่ได้โอนเงินคืนให้** ต้องคืนเงินลูกค้าเอง) ออเดอร์ที่จ่ายแล้วจะยกเลิกได้ก็ต่อเมื่อบันทึกการคืนเงินครบยอดแล้ว
- **ปิดร้านรายวัน:** ยอดรับแยกตามวิธีจ่าย ยอดคืน ยอดสุทธิ ยอดยกเลิก และรายการที่ยังไม่ได้รับเงิน กรอกยอดเงินเข้าบัญชีกับเงินสดที่นับได้ ระบบแสดงส่วนต่าง และบันทึกผลไว้ (แก้ภายหลังได้ แต่เก็บประวัติเดิมทุกครั้ง)
- **รายงานตามช่วงเวลา:** ยอดรายวัน และเมนูขายดี เลือกช่วงได้ไม่เกิน 93 วัน
- **ส่งออก CSV:** ออเดอร์ รายการอาหาร การคืนเงิน เปิดใน Excel ภาษาไทยได้ ข้อความที่ขึ้นต้นด้วย `=` `+` `-` `@` จะถูกใส่เครื่องหมายกันสูตรแฝง ทุกการส่งออกถูกบันทึกในไฟล์ข้อมูล
- **ยอดนับตามวัน-เวลาที่รับเงิน** ไม่ใช่เวลาที่สั่ง (สั่ง 23:50 จ่าย 00:10 ถือเป็นยอดของวันถัดไป) ควรยืนยันกับผู้ทำบัญชีก่อนใช้จริง
- **ยังไม่มี:** ภาษีมูลค่าเพิ่ม ใบกำกับภาษี/ใบเสร็จ รายจ่าย และการเทียบกับธนาคารอัตโนมัติ ตัวเลขในหน้านี้เป็นข้อมูลจากระบบสั่งอาหาร ไม่ใช่ตัวเลขทางบัญชีอย่างเป็นทางการ
- แยกสิทธิ์พนักงานและแอดมินแล้ว: PIN พนักงานดูออเดอร์และยืนยันรับเงินได้ แต่เข้าถึงเมนู ราคา ตั้งค่า และรายงานไม่ได้

## รูปอาหาร
- ในหน้า `/admin` → เมนู กด "เพิ่มรูป" ที่แถวของเมนู (เพิ่มเมนูก่อน แล้วค่อยใส่รูป) เลือกรูปหรือถ่ายจากมือถือได้เลย
- เบราว์เซอร์ย่อรูปให้เองเป็น JPEG ด้านยาวสุด 900px (รูปมือถือหลาย MB เหลือราว 30-300KB) เซิร์ฟเวอร์ตรวจซ้ำว่าเป็น JPEG จริงและไม่เกิน 600KB
- รูปที่เก็บอยู่ในโฟลเดอร์ `images` ถ้าย้ายหรือรีสตาร์ทโฮสต์โดยไม่มีดิสก์ถาวร รูปจะหาย
- ธีมหน้าตาเป็นโทนคาเฟ่ (ครีม น้ำตาล เขียวเซจ) แก้สีได้ที่ตัวแปรบนสุดของ `public/style.css`
- เมนูตัวอย่างมี 12 รายการ รวมหมวดเบียร์ (Leo และช้าง กระป๋องยาว ราคา 60 บาท) และหมวดของทานเล่น (เฟรนช์ฟรายส์ 30 บาท ลูกชิ้นทอดไม้ละ 10 บาท)

## ข้อจำกัดที่ควรรู้
- **ยังไม่ยืนยันการจ่ายอัตโนมัติ** ต้องมีคนกดรับเงินเอง (ถ้าอยากอัตโนมัติ ต้องต่อผู้ให้บริการรับชำระเงิน มีค่าธรรมเนียม ควรทำทีหลังเมื่อระบบนี้นิ่งแล้ว)
- **การชำระเงินใช้ QR บัญชีร้านของพนักงาน** ลูกค้าต้องพิมพ์ยอดเอง พนักงานควรแจ้งยอดให้ชัด และตรวจเงินเข้าบัญชีจริงก่อนกด "รับเงินแล้ว" เสมอ
- **ยกเลิกออเดอร์ได้เฉพาะพนักงาน** ถ้าลูกค้าจ่ายแล้วต้องคืนเงินเอง ระบบไม่คืนให้
- เก็บข้อมูลเป็นไฟล์เดียว เหมาะกับร้านเดียวที่ไม่ได้มีออเดอร์ถี่มาก ถ้าโตกว่านี้ค่อยย้ายไปฐานข้อมูลจริง
- ยังไม่มีเมนูหลายภาษา ตัวเลือกเสริม (ท็อปปิ้ง/ระดับความหวาน) หรือแยกบิลต่อโต๊ะ — เพิ่มได้ภายหลัง
